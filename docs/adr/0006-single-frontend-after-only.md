# ADR-0006: このリポジトリを After 専用にする（フロント1アプリ・スナップショット撤去）

- ステータス: Accepted
- 日付: 2026-08-10

## 背景

本リポジトリは tsunagu-works MVP のスナップショット（`api/` `web/`）を出発点とし、当初計画（設計プラン§4）では以下を予定していた:

- フロントエンドを `apps/company` / `apps/talent` の**2アプリに分割**（共有UIは `packages/ui`）
- スナップショットは Before として無傷で保持

Phase 0 でモノレポの骨格と生成パイプラインを作る中で、次の実感が得られた:

1. `apps/` の階層はアプリ数（実質 Go 1 + Next.js 1）に対して過剰
2. ウェルカム画面から作る `apps/company` より、**既存 `web/`（実装済みの23画面）を土台に作り替える**ほうが得るものが多い
3. Before の本体は元リポジトリ tsunagu-works に現存しており、**スナップショットの二重保持は不要**

## 決定

1. フロントエンドは **`web/` の1アプリ**とし、company / talent の2アプリ分割を取り下げる。ロール分岐はルートグループ（tsunagu-works で確立した型）で行う
2. 旧バックエンドのスナップショット `api/` は削除する（k6・旧CI・compose の app サービス等の周辺も撤去）
3. `apps/` 階層を廃止し、`api-server/` `web/` をルート直下に置く

**Before との比較は tsunagu-works リポジトリと行う。このリポジトリは After 専用。**

## 代替案と却下理由

| 案 | 却下理由 |
| --- | --- |
| 2アプリ分割を維持 | Cloud Run が2つ増える・共有UIパッケージの整備が必要・画面資産をゼロから作り直す。**個人開発の規模に対して分割の運用コストが利得を上回る** |
| スナップショットをリポジトリ内に保持 | 比較は元リポジトリと行えば足りる。同じコードの二重保持は「どちらが本物の Before か」を曖昧にする |
| Phase 2 まで判断を保留 | フロントの置き場が決まらないと #8（orval・フォーム）の生成先が決められない |

## 影響

- **バックエンドの設計は不変**: `internal/{company,talent,shared}` の視点分割・パスプレフィックス認可（[ADR-0003](0003-viewpoint-first-directories.md)）はフロント構成と独立して維持する
- `web/` は「無傷の Before」から「**作り替えの現場**」に役割が変わる（Stage 1 構成 → features / external 構成へ段階移行）
- `packages/ui` は前提を失い作らない。`packages/api-client` の要否（単一アプリでも独立パッケージにするか）は **#8 で再判断**
- 設計プラン§4 のフロント構成・デプロイ図（Cloud Run×2フロント）は本 ADR により読み替える
