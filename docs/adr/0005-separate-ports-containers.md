# ADR-0005: ポート・コンテナ名を tsunagu-works と分離する

- ステータス: Accepted
- 日付: 2026-08-08

## 背景

本リポジトリは tsunagu-works のスナップショットから出発しているため、docker compose の設定（ポート 5434/8081/3000・コンテナ名 `tsunagu-db` 等・ボリューム名）が元リポジトリと完全に同一だった。

このままでは:

1. **両リポジトリを同時に起動できない**（ポートとコンテナ名が衝突）——「2つを並べて比較する」という本リポジトリのゴールと矛盾する
2. **ボリューム名の共有により DB データを両リポジトリで共有してしまう**——スキーマが分岐した時点で事故になる

## 決定

ポートとコンテナ・ボリューム名を以下に分離する:

| 用途 | 本リポジトリ | 参考: 使用済み |
| --- | --- | --- |
| PostgreSQL | **5435** | 5432=ローカル・5433=todo-app・5434=tsunagu-works |
| Go API | **8082** | 8080=todo-app・8081=tsunagu-works |
| Next.js（company／現行 web） | **3001** | 3000=tsunagu-works |
| Next.js（talent） | **3002**（予約） | — |

コンテナ・ボリューム名は `tsunagu-arch-` 接頭辞（`tsunagu-arch-db` 等）。

## 代替案と却下理由

| 案 | 却下理由 |
| --- | --- |
| ポートだけ変える | コンテナ名の衝突と**ボリューム共有（DBデータ混在）**が残る。ポートより静かに壊れる分こちらが危険 |
| 環境変数でポートを切り替え可能にする | 既定値が衝突したままでは「設定し忘れたとき」に事故る。値を宣言的に固定して既定値自体を安全にするほうが確実 |

## 影響

- tsunagu-works と本リポジトリを同時に起動して Before / After を見比べられる
- DB データは完全に分離される。旧ボリュームのデータは引き継がれないため、切り替え後の初回は `make migrate-up && make seed` が必要
- `.env` / `.env.local` の実値はユーザーが手動で更新する必要がある（`.env.example` に新値を記載済み）
