# ADR-0009: 視覚回帰テストは導入せず、Storybook ビルドと play 関数を CI の検証線にする

- ステータス: Accepted（承認済み）
- 日付: 2026-08-18

## 背景

Storybook 導入（#38）にあたり、UI の視覚回帰（ピクセル比較）をどこまでやるかを決める必要がある。
AI が生成・リファクタする UI の安全網として視覚回帰は有効だが、方式によって
外部サービス依存・スナップショット管理・CI 時間のコストが大きく異なる。

現時点の UI は shadcn/ui の生成部品 + 少数の自作部品で、テーマのカスタマイズも
デザイン調整の反復もまだ始まっていない。

## 決定

視覚回帰（ピクセル比較）は**今は導入しない**。CI の検証線は次の2段にとどめる:

1. `build-storybook` を turbo タスクとして frontend-ci で実行（壊れた story = import 切れ・型エラーをビルドで検出）
2. play 関数（interaction test）は Storybook 上での目視・手動実行の資産として蓄積する（CI 実行は保留）

## 代替案と却下理由

| 案                                                                 | 却下理由                                                                                                                                                                   |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chromatic（無料枠 5,000 snapshots/月）                             | 最有力候補。ただし外部サービス依存とトークン管理が増え、現時点の UI 規模（自作部品十数個・テーマ未カスタマイズ）では検出したい差分がまだ無い。導入は発動条件を満たしてから |
| test-runner + Playwright スクリーンショット（CI アーティファクト） | 自前で完結する利点はあるが、ブラウザ起動込みで CI が数分延び、スナップショットの世代管理・閾値調整の運用コストが学習の主目的に対して過大                                   |
| スナップショット画像をリポジトリにコミット                         | レンダリング環境差（フォント・OS）で偽差分が頻発し、diff がバイナリでレビュー不能。採らない                                                                                |

## 影響

- 楽になること: CI は現状の速度（frontend 約30秒）を維持。外部サービス・シークレット追加なし
- 引き受けるリスク: 「見た目だけの退行」（余白・色・折返し）は CI で検出されず、Storybook の目視レビュー頼みになる
- **見直しの発動条件**（いずれかを満たしたら Chromatic 無料枠から再検討する）:
  1. shadcn 部品のカスタマイズやテーマ変更を始めるとき
  2. UI の意図しない差分事故が実際に起きたとき
  3. デザイン調整 PR のレビューが目視で追えない規模になったとき
- play 関数の CI 実行（@storybook/addon-vitest）も同じタイミングで再検討する
