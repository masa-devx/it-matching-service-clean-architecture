# デザインシステム — Tsunagu Works

> 決定日: 2026-08-03（Issue #7 着手時）。全画面はこのドキュメントに従う。
> 出典: 仕様デッキのブランド色 ＋ ui-ux-pro-max スキルの推奨（B2B SaaS / マーケットプレイス / 信頼訴求）を統合。

## コンセプト

**「信頼の設計」を体現するクリーン・プロフェッショナル**。
過度な装飾・アニメーションを避け、余白とコントラストで整える。ライトモードのみ（ダーク非対応）。

## スケール（余白・タイポ）

**任意の値を使わず、決まった段階から選ぶ**（モジュラースケール）。値がばらつくと、画面ごとに微妙に違う見た目になり「揃っていない感じ」の原因になる。

### タイポグラフィ

| 用途 | Tailwind | px | 使いどころ |
| --- | --- | --- | --- |
| 補足・注記 | `text-xs` | 12 | ヘルプテキスト・Badge |
| 本文小 | `text-sm` | 14 | 説明文・ラベル・カード内の情報 |
| 本文 | `text-base` | 16 | 入力欄（**モバイルで16px未満はiOSが自動ズームする**） |
| 小見出し | `text-lg` | 18 | セクション見出し |
| ページ見出し | `text-2xl` | 24 | h1（`PageHeader` が担当） |

- ウェイトは 400（本文）/ 500（`font-medium`: ラベル・強調）/ 700（`font-bold`: 見出し）の3段階
- 数値の表示は `tabular-nums`（桁が変わっても幅が揃い、一覧・カードのレイアウトが揺れない）

### 余白（4/8px グリッド）

| Tailwind | px | 使いどころ |
| --- | --- | --- |
| `gap-2` | 8 | 要素内の細かい間隔（Badge同士・アイコンと文字）※**タッチ要素間の最小値** |

- ページの縦構造は `flex flex-col gap-6` を基本とする
- カード内側の padding は `p-4`（16px）

## コンポーネント方針

- **shadcn/ui（radix・Nova）を標準**。角丸 `--radius: 0.625rem`・影は控えめ、デフォルトから触らない
- shadcn製は `components/ui/`、自作は `components/` 直下（ロール専用は `company/` `talent/`）
- アイコンは **Lucide** のみ（絵文字をアイコンにしない: 環境依存で見た目が変わる・CSSで制御できない・スクリーンリーダーが意図しない読み上げをする）
- **装飾のアイコンは `aria-hidden="true"`／アイコンのみのボタンは `aria-label`**（意味を持つか装飾かで扱いを変える）

### 共通レイアウト部品（自作）

| 部品 | 役割 | 使う場面 |
| --- | --- | --- |
| `PageHeader` | 見出し＋説明＋右側アクション | **全ページの先頭**（h1 はここに集約し、階層管理を1か所に） |
| `EmptyState` | アイコン＋説明＋次の行動 | 一覧が0件のとき。**「何も無い」で終わらせず導線を置く**（icon を必須プロパティにして強制） |
| `StatCard` | ラベル＋数値 | ダッシュボードの指標 |
| `Pagination` | ページ送り | 一覧（ページ番号はURLに持つ） |
| `ApplicationStatusBadge` | 選考状態のバッジ | 応募の一覧・詳細。**状態→ラベル・色・説明を1か所で定義**（`Record<ApplicationStatus, ...>` なので状態を足すとコンパイルエラー） |
| `ApplicationStatusFilter` | 選考状態での絞り込み | 応募履歴・応募者管理。**リンクなので RSC のまま完結**し、条件がURLに残る（`basePath` だけ差し替えて共用） |

### 導入済みの shadcn/ui 部品

`button` / `card` / `input` / `label` / `textarea` / `select` / `badge` / `separator` / `skeleton` / `sonner` / `sheet` / `alert-dialog`

- **生の `<select>` を使わない**: shadcn（Radix）の Select はキーボード操作・aria・フォーカス管理が組み込み済み。RHF とは `Controller` で繋ぐ（`register` は DOM 要素前提のため使えない）
- **タグ的な表示は Badge**（自前の `<span className="rounded-full...">` を書かない）
- トーストは `sonner`。描画先の `<Toaster />` はルートレイアウトに1つ
- **確認は `AlertDialog`**（`window.confirm` を使わない）。フォーカストラップ・Esc・role を Radix が担保する

### 状態ラベルの規約（選考）

| 状態 | ラベル | 誰の行為か |
| --- | --- | --- |
| applied | 応募済み | 人材が応募 |
| offered | オファー中 | 企業が声をかけた |
| accepted | 成立 | **人材が承諾**（ダブルオプトイン成立） |
| rejected | 見送り | **企業**が断った |
| withdrawn | 取り下げ | 人材が取り下げ |
| declined | 辞退 | **人材**が断った |

- **「見送り」と「辞退」は文字が似ていて、どちらが誰の行為か分からない**。バッジには必ず説明文（`applicationStatusDescription`）を添える
- ラベルは1か所（`ApplicationStatusBadge.tsx`）から取得する。バッジ・絞り込み・見出しで表記がズレないようにする

## フォームUX

### 入力
- ラベルは**常に表示**（placeholderをラベル代わりにしない）
- 必須項目は **`RequiredMark`**（`*` ＋ sr-only の「必須」）。記号だけでは意味が伝わらない
- `type="email"` 等のセマンティックな input type・`autocomplete` 属性を付ける
- 入力欄は **16px 以上**（`text-base`。モバイルSafariの自動ズーム防止）
- タッチターゲットは 44px 以上（`h-11` 目安）

### フィードバック（3層で伝える）

| 層 | 手段 | 用途 |
| --- | --- | --- |
| **一時的な結果** | **トースト**（sonner） | 保存成功・送信エラー。**本文中のテキストと併用しない**（同じ情報が2箇所にあると視線が分散する） |
| **項目ごとの問題** | フィールド直下のエラー（`role="alert"`） | どの入力を直すか |
| **全体の問題** | **`FormErrorSummary`**（フォーム上部） | 複数エラー時。該当フィールドへの `href="#id"` リンク付き・内部名でなく画面上のラベルを表示 |

- 送信中は **`SubmitButton`**（無効化＋スピナー＋文言変更の3点セット）。文言だけだと変化に気づきにくい
- 送信失敗時は最初のエラーフィールドへフォーカス（RHF の `shouldFocusError`・既定で有効）
- 入力量の多いフォームは **`useUnsavedChangesWarning`** で離脱確認
  - 制約: ブラウザ標準の文言のみ（カスタム不可）・Next.js のクライアント遷移は捕捉できない
- 検証は blur 時（入力中に赤くしない）

### 取り消せない操作の確認

- `AlertDialog` で確認を挟む。**説明文には「何が起きるか」を具体的に書く**（「本当によろしいですか？」だけでは判断材料にならない）
  - 良い例: 「承諾すると契約が成立します。条件をよく確認してから実行してください。」
  - 良い例: 「取り下げると選考は終了し、同じ案件に再度応募することはできません。」
- 実行中は**サーバー再取得（`router.refresh()`）の完了まで**ボタンを無効化する（`useTransition` の `pending` で追う）
- **失敗時も再取得する**: 409 は「表示していた状態が古かった」ことが大半なので、エラーを出して終わりにせず正しい状態を見せる

## 画面パターン

| 画面系統 | パターン |
| --- | --- |
| 認証（(guest)） | 中央寄せ単一カード・ロゴ→フォーム→切替リンクの縦一列 |
| 業務画面（company / talent の (authenticated)） | 共通ヘッダー（`AppHeader`）＋ `max-w-6xl` のコンテンツ。先頭に `PageHeader`、以降 `gap-6` で積む |
| 一覧 | 検索フォーム → 一覧（`gap-3`）→ ページャ。0件は `EmptyState` |
| 詳細 | 戻るリンク → `PageHeader` → 要約（グリッド）→ 詳細情報 → アクション |
| 選考の一覧（応募履歴・応募者管理） | `PageHeader` → **状態フィルタ**（`ApplicationStatusFilter`）→ カード一覧 → ページャ |
| LP（(public)） | 下記「LPの構成」を参照 |

### 選考の一覧に共通する規約

- カードは「**主題 → 判断材料 → 状態の説明 → 本文（折りたたみ）→ 操作**」の順
  - 人材の応募履歴: 案件名 → 企業名・応募日 → 状態の説明 → 志望動機 → 操作
  - 企業の応募者管理: 表示名 → 実務年数・スキル → 状態の説明 → 志望動機 → 操作
- **折りたたみの初期状態は読む必要性で決める**: 自分が書いた文章は閉じる／選考で必ず読むものは `open`
- 操作ボタンは**現在の状態で実行できるものだけ**描画する（`Partial<Record<ApplicationStatus, Action[]>>`）。終端状態では何も出さない
- 数字は `tabular-nums`。**0件のときは情報自体を出さない**（「0件が未対応」はノイズ）
- 「次にやること」だけ `text-primary` で強調する（未対応の件数など）

### LPの構成（Path selection パターン）

二面市場（企業⇔人材）のため、**来訪者がどちら側か分からない**。
一般的なSaaSの「無料で始める」1ボタンではなく、**最初に経路を分ける**（Enterprise Gateway の *Path selection*）。

| # | セクション | 役割 |
| --- | --- | --- |
| 1 | Hero | 一言価値 ＋ **企業/人材の2つの入口**（各ロールのsignupへ直行） |
| 2 | ProblemSolution | 企業・人材の課題を**一人称のカギカッコ**で並置し、解決策を対で示す |
| 3 | Features | 信頼の設計4本柱。**実装状況をBadgeで正直に表示** |
| 4 | HowItWorks | 利用の流れ（`<ol>` で順序をHTMLでも表す） |
| 5 | FinalCta | 末尾でもう一度入口（**ログイン済みなら非表示**） |

- **背景色の交互配置**でセクションを区切る（`bg-card` のセクションは `max-w-6xl` の外に置き全幅にする）
- LPのヘッダーは**ナビを持たない**（回遊させず入口へ進ませるのが目的。業務画面の `AppHeader` とは役割が違う）
- **ログイン状態はガードに使わず導線の出し分けにだけ使う**（LPはログイン後も見られるべき）
- フッターに**技術スタックとGitHubリンク**を置く（ポートフォリオとしての導線）

### 誠実さの規約

未実装の機能を「実装済み」と誤認させない。
- 機能紹介には**実装状況のBadge**（`default`=利用できます / `outline`=開発中）を付ける
- セクション末尾で「現在使えるもの」を明記する
- 信頼を価値とするサービスが自分の実装状況に不誠実だと、説得力そのものが失われる

- 装飾目的のグラデーション・過度なアニメーション（150–300ms のマイクロインタラクションまで）

## アクセシビリティ点検（2026-08-05 実施 / #75）

WCAG 2.1 AA を目安に点検。**優先度は影響の大きい順**（フォーカス・キーボード・コントラスト・aria が High）。

### コントラスト比（計算で検証）

| 組み合わせ | 実測 | 判定 |
| --- | --- | --- |
| 本文 `#0f172a` on 背景 `#f8fafc` | **17.06:1** | ✅ AA |
| 本文 `#0f172a` on カード `#ffffff` | **17.85:1** | ✅ AA |
| `muted-foreground` on カード | **4.74:1** | ✅ AA |
| `muted-foreground` on 背景 | **4.53:1** | ✅ AA（基準ぎりぎり） |
| primary上の文字 `#ffffff` on `#1d4ed8` | **6.70:1** | ✅ AA |
| primaryリンク `#1d4ed8` on カード | **6.70:1** | ✅ AA |

- 基準は本文 4.5:1（大文字は 3:1）。**`muted-foreground` は 4.53:1 と余裕が小さい**ため、これより薄い色を新設しない
- 計算は相対輝度（WCAG式）による。色を変えるときは再計算する

### 点検項目と結果

| 項目 | 優先 | 結果 |
| --- | --- | --- |
| フォーカスリング | High | ✅ shadcn の `focus-visible:ring-3` が全部品に適用済み。**`focus-visible` なのでマウスクリック時には出ない**（キーボード利用時のみ） |
| キーボード操作 | High | ✅ Sheet・Select は Radix がフォーカストラップと Esc を担保。`<details>` はブラウザ標準 |
| コントラスト | High | ✅ 上表のとおり全て AA |
| アイコンのみのボタン | High | ✅ `sr-only` で代替テキスト（メニュー開閉・条件チップの×）。装飾アイコンは `aria-hidden` |
| 見出し階層 | Medium | ✅ 各ページ h1 は1つ。**認証画面は `CardTitle asChild` で h1 を付与**（div のままだとページに h1 が無い状態だった） |
| スキップリンク | Medium | ✅ `SkipLink`（`sr-only` → `focus:not-sr-only`）を全レイアウトに設置 |
| タッチターゲット | — | ✅ 44px（`h-11`）を規約として全ボタンに適用 |
| 現在地の明示 | — | ✅ ナビに `aria-current="page"` |

### モバイル対応

- ヘッダーのナビは **md 未満で Sheet（ドロワー）** に格納（`MobileNav`）。Radix Sheet がフォーカストラップ・Esc・背景スクロール抑止を担保
- 検索フォームは `<details>` で折りたたみ（#73）
- グリッドは `sm:` / `md:` / `lg:` で段階的に列を増やす（モバイル1列が既定）

### 継続のルール

- 新しいUI部品を足したら**この表の項目を確認**する（特に High の4項目）
- 色を変えたらコントラストを再計算する
- アイコンのみの操作要素には必ず `sr-only` か `aria-label` を付ける
