---
description: Issueを選択してブランチを切り、開発を開始する
argument-hint: <Issue番号>（例: 3）
allowed-tools: Bash(git *), Bash(gh *)
---

Issue #$ARGUMENTS の開発を開始してください。手順：

1. `gh issue view $ARGUMENTS` でタイトル・本文（実装内容・受け入れ条件）・マイルストーン・ラベルを確認する
2. `git status` で未コミット変更が無いことを確認する（あれば中断してユーザーに知らせる）
3. `git checkout main && git pull origin main` で main を最新化する
4. ブランチを作成して切り替える：
   - 形式: `phase{N}/{Issue番号}-{内容}`（N はマイルストーン番号 M{N} と対応。内容は英小文字ケバブケース2〜3語）
   - 例: M0 の #3「api: signup」→ `phase0/3-signup`
5. **実装計画を提示して、ユーザーの承認を待つ**（承認前にコードを書かない）。計画に含めるもの：
   - 作成・変更するファイル一覧と各ファイルの役割
   - **コミット単位のステップ分割**（1ステップ＝1コミット目安・各ステップは単体でビルドが通る）
   - 使う技術・新出概念の予告
   - 各ステップの動作確認方法
6. 承認後、**ステップごとに止まりながら**実装する
   （実装 → ウォークスルー解説 → 動作確認の案内 → ユーザーのコードリーディング・コミットを待つ → 次のステップへ）
