# 開発ワークフロー

## ステップの型（todo-app 方式）

1. 1ステップ＝1つの小さな増分（例:「signup だけ」「一覧APIだけ」）
2. 実装 → **詳細解説（何を/なぜ/✅ベストプラクティス/⚠️アンチパターン）→ ユーザー確認 → コミット** の順を崩さない
3. 解説では、ユーザーが学習済みの内容（todo-app・react-basics・go-basics）と接続して説明する
4. 新出の概念・実務のコツ・ハマりは `docs/`（バックエンド.md / DB.md / フロントエンド.md）へ追記する
5. 各ステップに理解度チェック（自分の言葉で説明できるか）を添える

## やらないこと

- 一度に複数機能をまとめて実装しない
- ユーザーの確認なしにコミットしない
- サーバーの起動・停止（`go run` / `npm run dev`）は Claude が行わない（build/vet/test まで）
- push / PR はユーザーの明示指示があるときのみ

## リファクタ（R1〜R3）のとき

- 必ず `refactor/xxx` ブランチで行う
- 「なぜこのタイミングで層を分けるのか（どんな痛みが出たか）」を解説し、docs に記録する
